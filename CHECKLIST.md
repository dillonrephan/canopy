# Canopy Session Checklist

Use this page when returning to the project after a break. Keep it short,
literal, and current.

## Start of session

- Read `README.md` and this checklist.
- Run `git status --short --branch` before changing files.
- If the worktree is clean and time has passed, run `git pull --ff-only`.
- Confirm the intended branch and inspect the latest few commits.
- Read the documentation directly related to the active task.
- Run `./scripts/check.sh` before editing when environment or build state may
  have changed.
- Check `requirements-dev.txt` whenever dependencies are installed or changed.
- Before launching Canopy, close existing Canopy processes and start exactly
  one fresh instance.
- Prefer `./scripts/capture-virtual.sh` for inspection screenshots so the real
  desktop keeps its focused window.

If `canopy-dev` fails to start because `/run/avahi-daemon/socket` is missing,
check `avahi-daemon.socket`; the existing Toolbx binds that host socket.

## Active task: validate the active perspective presentation budget

Perspective math and renderer dispatch are now locked by tests:

- Perspective lane spacing is 160 units.
- Geometry is culled after the camera passes it rather than frozen nearby.
- Approaching growth moves lower, outward, larger, and clearer.
- Distant growth compresses toward the horizon and fogs.
- Reversing travel restores the exact prior projection.
- Extreme travel depths remain finite.
- Left/right lane ordering cannot flip.
- Non-root focus retains deterministic, profile-derived parent context in
  front of the focused trunk.
- Projection is bounded to six foreground corridors and two fog hints.

Projected geometry is now locked by tests:

- Every projected corridor has a closed tapered surface.
- The focused trunk begins at 130 pixels and narrows with perspective.
- Directory corridors are substantially wider than file stems.
- Hit geometry is generated by padding the exact projected surface.
- Hit geometry contains the complete surface without remote false targets.
- Culled nodes produce neither projected surfaces nor hit geometry.

Stage 6 is complete:

- The renderer paints the projected tapered surfaces rather than legacy lines.
- Hit-testing mirrors paint layers: visible labels/endpoints are considered
  first, followed by exact padded surface geometry in reverse depth order.
- The final frame showed a centered broad trunk, readable tapered corridors,
  correct near-over-far occlusion, and usable labels without planar transforms.
- Perspective input hints state that depth travel is not active yet.

Before implementing camera input:

- Exercise directories with more than eight projected children and confirm the
  six-foreground plus two-fog budget in paint and hit behavior.
- Check that overlapping focused-trunk and corridor targets resolve to the
  intended visible endpoint or near surface. This renderer-level layering is
  kept as a small shared-visibility code path but is not yet directly unit
  tested through `TreeSceneItem`.
- Decide how projected surfaces interpolate during focus/live transitions;
  preserve the current atomic geometry fallback until paint and hit can derive
  from one interpolated path.
- Treat live-removal departure animation as unresolved: removed semantic nodes
  are no longer available to `paintDeparting`, so their old surfaces may not
  fade even though focus departures and additions do.
- Keep the planar projector available until perspective navigation satisfies
  the same correctness and accessibility contracts.

See `docs/theme-architecture.md` for the full staged migration.

## Concept parking lot

### Recent-directory history

Start with the simplest implementation: a bounded vertical history list, not
Cover Flow.

- Record actual directory focus changes, not ordinary camera movement.
- Keep roughly 12 recent directory/viewpoint snapshots.
- Avoid adjacent duplicates.
- Restore directory identity, selected item, and saved view state.
- Support click, wheel while focused/hovered, Up/Down, Enter, Home/End, and
  visible keyboard focus.
- Provide literal names and paths for accessibility.
- Keep history semantics core-owned and its visual treatment theme-owned.
- A future Sakura presentation may replace the list with vertical iPod-style
  Cover Flow without changing the history model.

This is intentionally parked until the perspective projection and projected
hit geometry are trustworthy.

- Run `git diff --check` and the relevant tests.
- Update this checklist if the active checkpoint or next task changed.
- Commit coherent work before changing direction.
- Push the active branch and any new rollback tag.
- Verify `git status --short` is clean before calling the session safe to close.
